Security of the current site

  • exposed

    The admin username is literally admin, listed by the REST endpoint /wp-json/wp/v2/users and confirmed by /?author=1. The login page is open. That is half a brute-force attack handed over. Whether a rate limiter or two-factor exists is not visible from outside.

  • missing

    No security headers at all: no HSTS, no Content-Security-Policy, no X-Frame-Options, no X-Content-Type-Options.

  • surface

    WooCommerce installed and reachable with nothing to sell. More code, more future vulnerabilities, zero benefit.

  • check

    A Google Maps browser key sits in the page source. Normal for Maps, safe only if the key is restricted to this domain in Google Cloud. Unverified.

  • fine

    HTTP redirects to HTTPS correctly. XML-RPC appears blocked. Core version is current.

None of this says the site has been hacked. It says it is a typical unattended WordPress install, and you would be the last to know if it were.

Static site: what changes

You gain

No PHP, no database, no plugins, no login page, no admin panel, nothing to patch. GitHub serves flat files over HTTPS. Every change lives in Git history and can be undone. Hosting is free. Most of the security story is simply that there is nothing left to attack.

You lose

Anything a server did. Only two things did: emailing the contact form, and the WordPress editor. Editing becomes changing an HTML file, which with Claude is "change the phone hours" and done. Site search and blog comments also go; neither was used.

The hosting fine print you're not seeing

GitHub Pages' terms say it is not meant as free hosting for running an online business. Thousands of small-business brochure sites live there and GitHub has not enforced it against sites with no store, but it is a grey zone. Two free alternatives run the exact same folder, allow commercial use explicitly, and add what Pages cannot: custom security headers, a firewall, real redirects, and form handling. Keep the source on GitHub, deploy through Cloudflare Pages when ready. Starting on GitHub Pages to see it live today is fine; switching later is a DNS change, not a rebuild.

What you need to get your hands on

The cutover, in order

  1. David reviews the clone. It is 2017-era copy on purpose; edits come after the swap so the swap itself is invisible to Google and to the printed QR code on the door hanger.

  2. Wire the contact form endpoint and send a test. Add sitemap, robots, a 404 page, and the GA4 tag.

  3. Push the site to its own public repo and turn on Pages. Confirm it renders at the github.io address.

  4. Add the domain in the Pages settings and a CNAME file containing www.totaltreecareutah.com.

  5. At the registrar: www as a CNAME to myersmail9-afk.github.io; the bare domain to GitHub's four A records. Touch nothing else, especially MX. Wait for "HTTPS enforced" to go green, up to a day.

  6. Test both forms on the live domain. Scan the door-hanger QR code; it must open the homepage.

  7. Keep the old hosting for 30 days as a fallback, then cancel it and let the WordPress login die with it.

Security of the new setup, the whole list

  • do this

    Your GitHub account is the admin panel now. Turn on two-factor authentication and keep the recovery codes in the vault. Nobody else needs a login. This one control replaces every WordPress hardening plugin.

  • rule

    No secrets in the repo, ever. The form service's public key and a GA4 measurement ID are designed to be public. Nothing else belongs in the HTML. The existing secret guard already blocks tokens and .env files.

  • one click

    HTTPS enforced at the host.

  • ongoing

    Spam is the only real nuisance. The honeypot is in; add the form service's captcha if it gets bad.

  • theirs

    The Jobber widget runs on Jobber's servers, loaded exactly as the current site loads it.

  • built in

    Backups are Git history. Every version of every page, forever.

  • watch

    What could still go wrong: losing the GitHub login (recovery codes), the domain lapsing (auto-renew on, date in the calendar), the form vendor changing its free tier (swap one line).
